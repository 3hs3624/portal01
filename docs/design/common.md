# 공통 기능·UI·UX 설계

기준일: 2026-11-07. 적용 대상: 포털 및 세 웹 앱의 공통 화면. 앱 고유 동작은 앱별 설계서를 참조합니다.

## 1. 시스템 구성과 경계

GitHub Pages의 정적 포털이 동일 Origin의 앱 iframe을 열고 인증·권한·저장소·공유 API를 제공합니다. Write Studio는 `apps/markdown`, 프로젝트는 `apps/projects`, BI는 `apps/insight`입니다. 앱은 인증된 포털 부모 또는 허용된 상세 창 경로에서 실행합니다. 로그인 없이 앱 URL에 직접 접근하면 포털 로그인 경로로 이동합니다.

포털 SDK는 사용자 JWT로 Supabase Auth/RPC/Storage를 사용합니다. 프런트엔드에는 공개 키만 둡니다. 시스템관리의 초대·계정 삭제는 검증된 Edge Function과 관리 권한으로 처리합니다. 브라우저 작업공간, 외부 저장소 스냅샷, 항목 공유 작업공간은 별도 보관 단위입니다.

## 2. 포털 화면과 탐색

| UI/진입 | 조작·상태 전이 | 표시·보관·예외 |
|---|---|---|
| 초기 로딩 | 세션 및 서버 사용자·앱 권한 확인 | 확인 전 앱을 숨깁니다. 실패 시 연결 안내와 다시 시도를 표시합니다. |
| 이메일 입력 | 유효한 등록 이메일로 인증코드 요청 | 자동 신규 가입은 막습니다. 발송 여부를 단정하는 사용자 존재 노출을 피하고 재요청 대기 시간을 둡니다. |
| 인증코드 입력 | 코드 검증 후 계정 확인·앱 목록 로드 | 잘못된 코드·만료·중지 계정은 로그인 화면에 남기며 이유를 표시합니다. |
| 홈 | 앱 카드와 작업 요약으로 이동 | 서버 앱 읽기 권한과 사용자 표시 설정에 해당하는 앱만 노출합니다. |
| 애플리케이션 메뉴 | 앱 선택, 해시 경로 변경 | 앱 iframe을 전환합니다. 앱 내 작업 상태와 포털 탐색을 구분합니다. |
| 즐겨찾기 별 | 앱 즐겨찾기 추가·해제 | 계정별 브라우저 설정에 저장하며 메뉴 상단에 표시합니다. |
| 설정 | 앱 표시 체크, 위/아래 정렬, 즐겨찾기 표시 | 저장 시 적용하고 취소 시 기존 설정을 유지합니다. 저장 실패는 대화상자 안에 표시합니다. |
| 사이드바 접기 | 펼침↔축소 또는 앱별 재열기 레일 | 버튼의 이름·aria-expanded를 갱신하고 재열기 버튼을 유지합니다. |
| 사이드바 폭 | 오른쪽 경계 드래그, 방향키, Shift+방향키 | 현재 반응형 폭이 초기값입니다. 계정·앱별 폭 저장, 이중 클릭/Home 초기화, Esc 취소, 최소/최대 폭 제한. |
| 별도 창 | 앱 도구의 별도 창 열기 | 인증 포털 호스트를 포함한 `?appWindow=` 창에서 해당 앱만 전체 화면 표시. opener 제거, 팝업 차단 안내. |
| 테마·홈 | 앱별 밝게/어둡게 전환, 홈 복귀 | 테마는 앱별 브라우저 설정. 홈은 포털 경로로 이동합니다. |
| 로그아웃 | 현재 세션 종료 및 타 창에 전파 | 공유 인증 저장소를 지우고 다른 포털 창의 인증 UI도 종료합니다. |

브라우저의 같은 프로필·같은 Origin에서는 로그인 세션을 다른 탭/창에서 복원합니다. 다른 브라우저·개인 모드·설치형의 세션/로컬 데이터는 별개입니다. 서버 권한은 주기적으로 다시 확인하며 백그라운드 탭의 확인 시점은 지연될 수 있습니다.

## 3. 시스템관리

시스템관리 진입과 각 쓰기 버튼은 서버 권한에 따라 제한합니다. 화면에서 숨겼더라도 서버가 다시 권한을 검증합니다.

| 영역 | 기능·UX | 보호·실패 처리 |
|---|---|---|
| 사용자 | 검색/목록, 초대, 상태 변경, 이용 중지·재활성화, 역할·그룹 연결 | 읽기 전용 관리 권한에는 쓰기 제어를 숨깁니다. 변경 결과·오류를 화면에 유지합니다. |
| 초대 | 관리자가 이메일 입력 후 등록 안내 메일 요청 | 일반 역할로 초대, 서버에서 요청자 검증. 재요청/발송 빈도 제한. 결과 불명 시 자동 재발송하지 않습니다. |
| 역할·권한 | 역할별 시스템/앱 읽기·쓰기 권한 관리 | 클라이언트가 보낸 관리자 ID/역할을 권한 증거로 사용하지 않습니다. |
| 그룹 | 구성원 및 그룹 역할 관리 | 사용자 역할과 그룹 역할의 유효 권한을 서버에서 계산합니다. |
| 계정 삭제 | 확인 절차·이메일 재입력 후 영구 삭제 | 본인·마지막 활성 관리자 보호. 인증 계정·클라우드 행·첨부 정리 결과를 확인합니다. 이용 중지와 구분합니다. |
| 로그 | 접속·관리 변경 이력 조회, 관련 필터/페이지 이동, 허용된 삭제·보관 설정 | 권한 있는 관리자만 접근. 보관 정책·정리 실행은 서버 기능을 사용합니다. |

관리 현황은 사용자·활성 사용자·그룹·역할·최근 24시간 접속 수를 표시합니다. 목록 검색과 50개 단위 이전/다음 페이지를 제공합니다. 사용자 표는 이메일·표시 이름·상태·직접 역할·최근 인증 로그인·관리, 그룹은 이름·설명·구성원·역할 수, 역할은 이름·코드·설명·권한 수를 표시합니다.

사용자 수정은 표시 이름/상태와 별도 역할 선택을 구분합니다. 그룹은 이름·설명·구성원 체크 목록·그룹 역할을 관리하고, 그룹 역할 선택에서는 시스템 관리자 역할을 제외합니다. 역할은 코드·이름·설명·고정 권한 체크 목록으로 구성하며 기본 역할의 제한을 유지합니다. 고정 권한 카탈로그는 삭제하지 않고 역할에서 부여 범위를 바꿉니다. 편집 대화상자는 저장/취소/서버 오류와 진행 중 버튼 잠금을 제공합니다.

초대는 같은 이메일 10분 내 재요청, 관리자별 분당 5건, 전체 하루 100건 제한을 사용합니다. 로그 보관 설정은 1~3650일, 기본 180일, 자동 정리 켜짐 여부를 입력합니다. 자동 정리는 설정된 경우 한국시간 오전 3시에 보관 기간이 지난 로그를 대상으로 하고, 즉시 정리는 별도 영구 삭제 확인을 거칩니다. 접속 로그는 인증 계정의 포털 보고 이벤트이며 IP·인증 실패·완전한 보안 감사는 Supabase Auth 로그와 구분합니다.

실제 메일 전달·외부 이메일 서비스의 상태는 모의 UI 검증과 별도입니다. 서버 중지는 이미 열람한 내용의 소급 회수를 의미하지 않습니다.

## 4. 공통 저장소 UX

| 단계 | UI와 입력 | 결과·취소·예외 |
|---|---|---|
| 위치 선택 | 브라우저 / Supabase / 로컬 폴더 / OneDrive / Google Drive | 위치 선택만으로 현재 작업이나 저장본을 덮어쓰지 않습니다. 클라우드 동기화 폴더는 PC의 폴더 선택 방식입니다. |
| 폴더 연결 | 디렉터리 선택, 기존 핸들 권한 재승인 | File System Access API·사용자 제스처가 필요합니다. 지원/권한 오류는 안내하고 기존 작업을 유지합니다. |
| 상태 비교 | 현재 작업·대상 저장본의 항목 수·생성/수정/저장 시각 | 생성일이 최신 내용의 증거는 아닙니다. 저장소 저장 시각과 개별 항목 수정 시각을 구분합니다. |
| 작업 선택 | 현재 작업 저장 / 저장본 불러오기 / 비교·합치기 | 적용 전 검토 화면을 거칩니다. 취소 시 실제 데이터는 바꾸지 않습니다. |
| 충돌 선택 | 현재 작업 / 저장본 / 둘 다 보관 | ID와 내용으로 비교하고 불명확하면 둘 다 보관을 권장합니다. 앱별 참조 ID도 보존/재연결합니다. |
| 백업 | 현재 작업과 교체 대상 백업, 목록·JSON 내리기/가져오기/복구 | 계정별 IndexedDB 최근 10개. 백업이 실패하면 교체하지 않습니다. 폴더는 previous 파일도 유지합니다. |
| 실행 | generation·revision·fingerprint 재확인 | 검토 뒤 작업/저장본이 바뀌면 재검토하도록 중단합니다. 서버 CAS를 강제로 무시하지 않습니다. |
| 잠금·열린 창 | 문서 불러오기 중 편집 제한, 프로젝트/BI 상세 창 확인 | 전체 교체 중 열린 편집 창이 있으면 앱 계약에 따라 저장/닫기 또는 적용 중단을 안내합니다. |

기본 작업 자동저장은 브라우저에 이루어집니다. 개인 외부 저장소 반영은 사용자가 공통 저장소 흐름에서 실행합니다. 공유 작업공간의 저장은 공유 API에 반영되므로 개인 외부 저장소 자동 전송과 구분합니다.

클라우드 설정 안내 페이지는 초기 SQL을 텍스트 영역으로 제공합니다. 페이지 자체가 관리자 SQL을 실행하지 않습니다. 현재 관계형 저장·시스템 권한·공유까지 구성할 때는 기존 기술 문서와 실제 마이그레이션 순서를 함께 참조합니다.

## 5. 데이터·파일 계약

| 대상 | 형식/구성 | 보존·권한 |
|---|---|---|
| Write Studio | `md-editor-workspace` v1, documents/folders/activeId/theme | Supabase 문서·폴더·태그·댓글 관계형 행 + 유동 속성 JSONB. 본문 블록은 Markdown/HTML 메타데이터로 보존. |
| Project Management | `wbs-pm-cloud` v1의 directories/files | Supabase 프로젝트·WBS 관계형 행, 파일 manifest, 비공개 내용 해시 첨부. 원본 엑셀 바이너리 보존. |
| Insight BI | `insight-bi-workspace` v1, dashboards/sources/detached/theme | 대시보드·카드·소스·시트·열·행·링크 관계형 행 + 설정/행값 JSONB. |
| 폴더 | `3HS-Workspace/<앱 폴더>/workspace.json`, previous 저장본 | 실제 선택 폴더 권한으로 읽고 씁니다. 기존 프로젝트 `WBS-PM/projects` 형식도 유지합니다. |
| 용량 | 클라우드 전체 작업공간 계정·앱별 100MiB, 별도 브라우저/폴더 49MB | 문서 1개 5MiB 등 앱별 제한 별도. 플랫폼 요금제 전체 용량 변경을 뜻하지 않습니다. |
| 개인 데이터 | 사용자 해시로 localStorage/IndexedDB 이름 분리 | 공유는 여기에 공유 ID를 추가해 개인 저장소와 분리합니다. |

개인 관계형 저장은 계정 소유권과 앱 권한을 RLS에서 확인합니다. 외부 전체 작업공간 저장은 트랜잭션, 이전 버전 백업, expected revision을 사용합니다. JSONB 객체 키 순서만 바뀐 경우 내용 변경으로 보지 않습니다.

## 6. 항목 공유의 상세 UX

1. 문서 행/프로젝트 관리/대시보드 관리의 `공유`를 누릅니다. 선택한 항목의 이름과 공유 범위를 표시합니다.
2. 등록 사용자 검색창에 이름/이메일을 입력합니다. 활성·확인된 계정 중 해당 앱 접근 권한이 있는 사용자를 반환하며 소유자는 제외합니다.
3. 체크박스는 행 맨 왼쪽, 이름·이메일은 오른쪽입니다. 긴 문자열은 줄바꿈하며 라벨 클릭으로도 선택합니다. 검색을 바꿔도 선택 ID 집합·선택 인원은 유지합니다.
4. 조회/편집 권한을 선택하고 선택 사용자에게 공유합니다. 선택 없음은 오류, 편집 권한 부족 수신자는 서버가 거부합니다. 일부 요청 실패 시 적용된 인원과 미완료 상태를 표시하고 멤버 목록을 다시 확인합니다.
5. 최초 공유 확정 시 공유 작업공간을 만듭니다. 확정 전 취소하면 공유본을 만들지 않습니다. 개인 원본은 보관하며 공동 작업은 공유 항목에서 합니다.
6. 수신자는 `공유받은 항목`, 소유자는 `내가 공유한 항목`에서 엽니다. 목록 새로고침을 제공하고 개인 원본 삭제 후에도 소유자의 열기/권한 관리를 유지합니다.
7. 공유 창의 멤버별 권한 선택과 공유 해제는 소유자만 가능합니다. 편집 수신자는 저장할 수 있지만 재공유/권한 관리는 할 수 없습니다.
8. 공유 항목은 별도 전체 작업공간 대화상자에서 해당 앱을 엽니다. 상단에 조회 전용/편집 가능, 저장 상태, 저장 버튼, 최신 내용 다시 열기를 표시합니다. 닫기·재열기는 미저장 변경 확인을 거칩니다.
9. 조회 전용은 원본 편집 제어를 제한하며 서버도 저장을 거부합니다. 권한은 약 15초마다 재확인하고 서버는 매 요청마다 검사합니다. 일시적 연결 실패는 편집 프레임을 제거하지 않습니다. 권한 상실/로그인 변경은 접근을 중단합니다.
10. 저장은 revision 충돌 검사를 사용합니다. 먼저 저장한 내용이 있으면 덮어쓰지 않고 다시 열도록 안내합니다. 직전 3개 저장본을 보관합니다. 실시간 타이핑 병합·알림 발송 기능은 아닙니다.

공유 단위는 문서 하나, 프로젝트 하나의 파일 묶음, 대시보드 하나와 연결 시트 하나입니다. 다른 문서·하위 페이지·프로젝트·시트는 자동 공개하지 않습니다. 항목당 25MB, 소유자 현재 공유 데이터 합계 100MB를 확인합니다. 비공개 `portal_sharing` 테이블 직접 접근은 금지하고 공개 invoker RPC → 비공개 검증 함수로 접근합니다. 마이그레이션은 `20261106233329_item_level_sharing`입니다.
