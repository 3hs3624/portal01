# Project Management 상세 기능·UI·UX 설계

기준일: 2026-11-07. 프로젝트 목록 앱과 새 창의 WBS 대시보드를 하나의 업무 흐름으로 정의합니다. 공통 저장소·권한·공유는 [공통 설계](common.md), 컨트롤 ID·입력·선택지는 [UI 인벤토리](ui-inventory.md)를 참조합니다.

## 1. 화면·진입과 기본 상태

앱 헤더, 작업공간 사이드바(프로젝트/저장소), 프로젝트 제목·등록/백업/엑셀 등 작업, 검색/필터, 상태 집계, 가로 스크롤 가능한 표, 건수·페이지 이동·페이지 크기로 구성합니다. 현재 저장소가 없거나 접근 권한이 없으면 목록 대신 연결/권한 안내를 표시합니다. 프로젝트가 없을 때는 빈 화면에서 새 프로젝트 등록으로 진입합니다.

프로젝트 이름/관리의 열기는 별도 대시보드 창을 요청합니다. 창이 이미 열렸으면 기존 창을 활성화하고, 팝업이 차단됐으면 허용 안내와 등록 결과를 분리해 표시합니다. 목록에서 공유 연결된 프로젝트를 열면 공유 작업공간으로 이동합니다.

| 진행 상태 | 제안/착수 준비/진행 중/검수/완료/보류 또는 전체 | 사용자가 지정한 업무 상태 기준으로 필터링. 일정 지연과 별개입니다. |

| 관리 | 새 창 열기, 기본정보 수정, 공유 | 권한·저장소 준비·공유 컨텍스트에 따라 제어를 제한합니다. |

프로젝트 목록 엑셀은 화면의 현재 페이지만이 아닌 해당 내보내기 계약의 프로젝트 목록 전체를 대상으로 합니다. 이름·설명 등이 `=` 등으로 시작해도 의도하지 않은 엑셀 수식으로 변환하지 않습니다.

## 4. WBS 대시보드 화면과 탐색

상단 프로젝트/저장소/마지막 저장 상태, 주요 메뉴·탭, 요약 지표·단계별 진척, 지연/주의 태스크, WBS/간트, 기준정보, 데이터 점검, 엑셀 연동, 저장 이력·변경 내역·비교, 가이드를 제공합니다. 구체적인 탭/버튼/입력 ID는 대시보드 HTML을 복호화한 인벤토리에 별도 표기합니다.

탭 이동은 표시 화면을 바꾸며 저장과 구분합니다. 저장 전 작업 내용은 창의 현재 작업본으로 유지됩니다. 프로젝트 기본정보는 호스트 목록에서 저장한 값과 현재본을 함께 사용합니다. 독립 HTML 내보내기와 포털 저장소에 연결된 창을 구분하여 저장 위치·가능한 동작을 표시합니다.

## 5. 샘플 유지 또는 빈 WBS

샘플 표시는 실제 프로젝트 자료와 예시 단계를 구분합니다. `sample 유지 또는 빈 WBS`에서 현재 WBS를 유지하고 샘플 표시를 해제하거나, 확인 후 샘플 단계/태스크를 삭제해 빈 WBS로 시작할 수 있습니다. 취소는 기존 작업을 보존합니다. 빈 WBS 전환은 확인 상태를 거쳐 실수로 초기화하지 않게 합니다. 실제 WBS를 전체 교체해 올리면 샘플 상태 해제 계약을 적용합니다.

| 수준/제어 | 입력·조작 | 계산·저장·예외 |

단계·Activity·태스크는 안정 식별자와 속성을 유지합니다. 화면과 JSON의 계획/실적 날짜, 진행률, 추가 속성을 상호 변환합니다. UI에 없는 확장 속성을 저장 시 불필요하게 삭제하지 않습니다.

## 7. 간트·진척·주의 상태

- WBS 행의 계획/실적 일정과 진척을 간트에 표시하고 기준일·마일스톤·공휴일을 반영합니다.
- 이전/다음 기간, 오늘, 기준일 이동으로 시간축을 탐색합니다. 가로/세로 스크롤은 데이터 편집과 분리합니다.
- 단계별 계획·실적, 전체 진척, 지연·주의 태스크를 요약합니다. 진행 상태(사용자 지정)와 일정 상태(일정 산정)를 별도로 표시합니다.
- 설정 변경 미리보기와 실제 적용을 구분하고, 실제 WBS가 없는 빈 화면은 예시 데이터를 실제 실적으로 오인하게 표시하지 않습니다.
- 정확한 산식·서식·범례는 현재 템플릿 코드/엑셀 서식이 기준입니다. 원본 워크북이 있는 경우 동일한 산식/조건부 서식 왕복 검증을 함께 수행해야 합니다.

### 진척·지연 산정 규칙

태스크 진척 `K`는 입력 퍼센트를 0~1로 제한합니다. 유효한 계획 시작/종료가 있으면 `E`는 해당 기간의 계산 영업일 수, 없거나 종료가 앞서면 0입니다. 기준일이 계획 시작 전이면 경과 계획 공수 `J=0`, 종료 후이면 `J=E`, 기간 안이면 시작~기준일 영업일 수입니다. 실적 공수 `L=E×K`입니다.

태스크 계획률은 `E>0 ? J/E : 0`, 실적률은 `K`입니다. 상위 Activity·단계·전체는 하위 태스크의 E/J/L을 합산하여 계획률 `ΣJ/ΣE`, 실적률 `ΣL/ΣE`를 계산합니다. 단순 태스크 퍼센트 평균과 구분합니다. 상위 기간은 하위 최소 시작/최대 종료이며 전체 완료 조건 전에는 실제 종료 집계를 완료로 확정하지 않습니다.

진척 100%는 완료, 실제 시작이 있거나 진척이 0 초과면 진행, 나머지는 미착수입니다. 계획 종료가 기준일보다 지났는데 미완료면 종료 지연, 미착수인데 계획 시작이 지났으면 착수 지연, 완료했으나 실제 종료가 계획 종료보다 늦으면 지연 완료입니다. 지연 일수도 계산 영업일 기준입니다. 계획 대비 실적 차이는 %p로 표시하며 주의/위험 임계값은 기준정보 설정을 따릅니다.

엑셀 간트는 주간 계획 겹침, 실적 겹침, 계획 밖 실적, 상위 집계, 기준일 주간을 구분합니다. 현재 채움색과 조건부 서식 규칙을 함께 기록하고, 재계산 후 오래된 색이 남지 않도록 초기화 규칙을 둡니다.

## 8. 엑셀 업로드·다운로드 상세

| 흐름 | UX/처리 | 보존·제약 |
|---|---|---|
| 목록 내려받기 | 프로젝트 목록 내보내기 | 페이지 밖 항목, 한글, 날짜, 비율, 빈 요약, 수식처럼 보이는 일반 문자열 처리. |

| 파일 선택 | 파일명·지원 형식·용량 확인 | 불러오기 오류를 표시하고 현재 작업본 보존. 라이브러리 로드 실패 후 재시도 가능. |
| 읽기/매핑 | 원본 시트·기준일·행 대응 읽기 | 데이터 점검/적용 결과 미리보기. 원본 데이터로 되돌리기·다른 파일 선택·취소. |
| 적용 | 작업본 반영 또는 전체 교체 | 예시 상태 해제, 프로젝트 기본정보와 WBS 정합성 유지. |
| 원본 유지 왕복 | 원본 워크북 바이너리와 행 매핑을 보관하고 변경 셀 갱신 | 수식, 스타일, 조건부 서식, 간트 색상, 추가 시트 보존 경로 사용. |
| 구조 변경 | 태스크/행 배치가 원본 매핑과 달라짐 | 원본 그대로의 셀 대응이 불가능한 변경은 새 레이아웃/해당 안내 계약 사용. 무조건 동일 원본 보존이라고 표시하지 않음. |

ExcelJS와 `workbook-preserve.js`/fflate를 사용합니다. 테스트는 파일을 열 수 있는지만 확인하지 않고 수식·서식·조건부 서식·간트 색상·원본 파일 구조를 확인합니다. 별도 sample 파일 비교는 해당 fixture를 제공한 검증과 일반 구조 검증을 구분합니다.

## 9. 저장·이력·비교·충돌

| 화면/조작 | 상태와 결과 |
|---|---|
| 저장 | 이름·메모·작성자 등 스냅샷 정보를 입력해 네이티브 프로젝트 이력을 기록합니다. 마지막 저장·revision·요약을 갱신합니다. |
| 저장 위치/저장소 | 현재 위치·연결 상태·저장 가능 여부를 표시합니다. 연결 해제/권한 만료면 저장을 막고 이유를 안내합니다. |
| 저장 이력 | 스냅샷 목록, 선택본 열람, 작업본 복원, 보기 종료 | 과거본 보기와 현재 작업본 편집을 구분합니다. |
| 변경 내역 | 현재/이전본의 변경과 요약 | 추가·삭제·수정 항목을 비교합니다. |
| 스냅샷 A/B 비교 | 비교 대상 선택, 순서 교환, 요약·단계 실적·변경 내역 | B 내용을 작업본으로 불러오기, 비교 HTML 내보내기 등을 명시적 실행으로 처리합니다. |
| JSON 불러오기 | 현재본과 비교/작업본 반영 선택 | 취소/원래 데이터/다른 파일을 제공. 잘못된 패키지는 기존 작업 유지. |
| 동시 저장 충돌 | 저장 전 revision이 달라짐 | 다른 사용자가 먼저 저장했음을 표시하고 최신본 불러오기 또는 명시적 덮어쓰기 확인을 제공합니다. 공통 저장소 흐름에서는 강제 무시하지 않습니다. |
| 동기화 충돌 사본 | 파일 시스템이 만든 별도 파일 감지 | 목록에 경고·경로 표시, 임의 원본 선택/삭제는 하지 않습니다. |
| 전체 외부 저장 | 열린 대시보드의 초안 포함 비교·백업 후 저장 | 실제 반영 때 네이티브 저장을 먼저 수행. 외부 전송 실패가 이미 기록한 네이티브 이력을 삭제하지 않습니다. |

## 10. 데이터·저장 구조

- 폴더: `WBS-PM/projects/<ID>.meta.json`, `<ID>.json`, `<ID>/snapshots/*.json` 및 관련 엑셀. 메타는 목록 기본정보/진척 요약/최종 저장을 빠르게 표시합니다.
- 패키지: `wbs-dashboard`의 projectId/current/snapshots/revision 계열. 현재 스키마의 인덱스와 스냅샷 파일에서 이전 호환 패키지를 재구성합니다.
- 현재본: project, settings, phases→activities→tasks, holidays, milestones, sample, 원본 excelTemplate 및 추가 속성.
- 브라우저 작업 사본: `PortalCloudFiles`의 파일/폴더 가상 핸들과 계정별 IndexedDB. 선택한 로컬 폴더의 File System Access 핸들과 동일한 호출 계약을 제공합니다.
- Supabase: portal_pm_workspaces/projects/phases/activities/tasks/calendar/files/versions/backups 및 비공개 프로젝트 첨부 버킷. 원본 엑셀은 해시·크기 검증 후 사용자별 경로에 저장합니다.

사용자별 RLS·앱 읽기/쓰기, 예상 revision, 파일 경로/개수/용량, JSON 및 바이너리 무결성을 확인합니다. 공유에서는 동일한 네이티브 형식을 사용하되 사용자·공유 ID별로 분리하고 조회 사용자의 저장을 서버에서 차단합니다.

## 11. 구현·검증 맵과 현재 경계

주요 목록·파일·대시보드 호스트 코드는 `apps/projects/index.html`입니다. 내장 `dash-tpl`은 gzip/base64 HTML이며 사람이 수정할 때 원문 추출→수정→재인코딩과 CSP hash 갱신이 필요합니다. 대시보드의 UI도 인벤토리에 별도 추출합니다.

- 엑셀: `workbook-preserve.js`, `vendor/exceljs.min.js`, `vendor/fflate.min.js`, `tests/projects_excel.py`.
- 샘플 선택: `tests/projects_sample_choices.py`.
- 파일·관계형: `cloud-files.js`, `project-cloud.js`, `storage-adapters.js`, `portal-projects-relational.sql`, `portal-projects-consistency.sql`, `tests/project_cloud.cjs`, `tests/project_relational_*`.
- 공통 저장/복구: `tests/shared_storage_flow.py`, `storage_models.cjs`, `folder_storage_conflicts.cjs`.
- 공유/패널: `tests/item_sharing_ui.py`, `item_sharing_sql.mjs`, `sidebar_layout.py`.

웹은 브라우저 팝업·폴더 권한 및 PC 동기화 앱에 의존합니다. 설치형은 아직 호환성 프로토타입이며 WBS 새 창·파일 접근의 전체 실기기 지원을 완료한 것으로 취급하지 않습니다. 세부 현재 범위는 설치형 설계를 따릅니다.

## 저장·엑셀 검사·지연 근거 개선 (2026-11-08)

- 상단 공통 저장 상태는 브라우저 작업 사본의 저장과 선택 저장소 반영을 구분합니다. 실제 프로젝트 폴더에 저장한 경우에는 프로젝트 폴더 저장 완료로 표시합니다. 열린 WBS 변경 포함 저장·불러오기 전 열린 창 확인·양쪽 백업은 기존 흐름을 유지합니다.
- 개인 프로젝트의 공유 연결 배지, 공유 목록의 소유자·권한·서버 수정 시각을 표시합니다. 공통 저장소 기본 화면에서 변경 이력·백업 목록으로 바로 진입합니다.
- WBS 엑셀 업로드 미리보기에는 원본 OOXML의 수식 수, 조건부 서식 규칙 수, 스타일이 지정된 셀 수를 표시합니다. 기존 현재 작업 대비 변경 표와 전체 교체/일정·진척 반영 선택을 함께 확인합니다. 원본 보존 모듈을 사용할 수 없는 별도 HTML 실행에서는 검사 개수를 추정하지 않고 원본 보관 안내를 표시합니다.
- 같은 구조로 원본을 보존하여 내려받을 때 수식·조건부 규칙·서식 셀 개수가 원본보다 줄지 않았는지 다시 검사합니다. 검사 실패 시 다운로드를 중단합니다. 이는 구조 검사이며 수식 결과 계산을 대신하지 않습니다. 기존 원본 수식·다른 시트·서식 보존과 Excel 재계산 설정을 유지합니다. WBS 행 구조가 달라 새 양식으로 내보내는 경우 기존 안내를 유지합니다.
- 목록의 일정 상태가 지연이면 계획 대비 실적 부족 %p 또는 사업 종료일 경과를 함께 표시합니다. 이는 현재 요약으로 판정한 근거이며 담당자·태스크의 원인을 추정하지 않습니다. 완료·예정·진행의 판정 기준은 유지합니다.

검증: projects_excel.py --format-fixture(실제 XLSX·수식·사용자 서식·조건부 서식 왕복·CSP), shared_storage_flow.py, storage_feedback.py, item_sharing_ui.py.
