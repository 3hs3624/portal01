# Write Studio 저장소

화면·백업·충돌 보호는 세 앱이 공유하는 공통 모듈을 사용합니다. 전체 구조는 [공통 저장소 관리](../../STORAGE-MANAGEMENT.md)를 참고하세요.

문서 편집은 브라우저 작업공간에 자동저장합니다. 저장소 화면은 별도의 스냅샷을 저장하거나 가져오는 흐름입니다. 폴더를 고르는 것만으로 기존 작업이나 저장본을 바꾸지 않습니다.

1. 저장할 위치를 고릅니다. 로컬·OneDrive·Google Drive는 PC 폴더를 선택합니다. 기존 폴더 접근이 거부되면 접근 권한 다시 승인으로 연결을 복구합니다.
2. 현재 작업과 저장본의 문서 수, 첫 문서 생성, 최근 수정, 저장소 저장 시점을 확인합니다.
3. 현재 작업 저장, 저장본 불러오기, 문서별 비교·합치기를 선택한 뒤 검토 화면에서 실행합니다.

문서 비교는 생성일·수정일·이름순으로 정렬하고, 본문과 태그·댓글을 나란히 볼 수 있습니다. 생성일은 새 내용의 우선순위를 뜻하지 않습니다. 최근 수정일 추천은 유효한 수정일끼리 비교하며, 날짜가 같거나 불명확하면 둘 다 보관을 권장합니다. 사용자가 적용하기 전에는 실제 문서를 바꾸지 않습니다.

합치기는 문서 ID를 기준으로 양쪽에만 있는 문서를 보존합니다. 충돌은 현재 작업·저장본·둘 다 보관으로 선택합니다. 둘 다 보관은 저장본 사본에 새 ID와 `(저장본)` 제목을 부여합니다. 같은 폴더 경로는 합치고, 폴더 ID가 충돌하는 다른 경로는 새 ID로 보존합니다. 문서 500개·폴더 200개 등 기존 작업공간 제한을 초과하면 적용 전에 중단합니다.

저장·불러오기·합치기 전에 현재 작업과 교체 대상 저장본을 계정별 IndexedDB에 백업합니다. 최근 10개를 목록에서 비교·복원·JSON 다운로드할 수 있으며, 이전 저장소 화면의 복구본도 가져옵니다. 현재 작업 JSON을 바로 내리거나 백업 JSON을 가져올 수도 있습니다. 백업 실패 시 교체를 실행하지 않습니다. 폴더 저장은 기존 `workspace.previous.json` 보관도 유지합니다. 백업에는 문서와 폴더 구성이 포함되며, 링크된 외부 파일의 실제 바이너리는 별도로 보관합니다.

적용 전 최신 revision과 payload를 검증하고, 저장은 기존 expected-revision API로 수행합니다. 폴더는 저장 시작과 직전의 payload도 비교하여 revision을 유지한 수동 편집을 탐지합니다. 다른 탭·기기에서 바뀐 저장본을 강제로 덮어쓰지 않습니다. 쓰기 전후에 현재 작업 generation도 확인합니다. Supabase 인증·앱별 권한·100MB 제한과 브라우저/폴더 49MB 제한은 기존 API를 사용합니다. 새 데이터베이스 권한이나 스키마 변경은 없습니다.
